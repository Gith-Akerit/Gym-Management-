เอกสารนี้ใช้สำหรับนำระบบขึ้นอินเทอร์เน็ตให้คนนอกเข้าใช้ได้จริง
ถ้าจะรันบนเครื่องตัวเองเพื่อลองดูเฉย ๆ ให้ดูหัวข้อ "เริ่มใช้งานบนเครื่องพัฒนา" ใน [`README.md`](../README.md) แทน

สำหรับ pilot บน `srv1979069.hstgr.cloud` มีตัวติดตั้งผ่าน Browser Terminal ที่ [docs/bootstrap.md](bootstrap.md): รับอีเมลและรหัสผ่านของแอดมินคนแรกแบบไม่แสดงบนจอ แล้วตั้งค่าที่เหลือให้เอง ใช้คำสั่งที่ pin commit จากความเห็นส่งมอบของ Infrastructure Engineer

## สรุปก่อนเริ่ม

ระบบเป็น Node.js ตัวเดียว เสิร์ฟทั้ง API และหน้าเว็บ เก็บข้อมูลทั้งหมดเป็น **ไฟล์บนดิสก์** ไม่ได้ใช้ฐานข้อมูลแยก

| เก็บอะไร | ที่ไหน |
|---|---|
| สมาชิก แพ็กเกจ คำสั่งซื้อ สิทธิ์ ประวัติเช็คอิน audit log · ตั้งค่ายิม (สี/ชื่อย่อ/LINE) | ไฟล์ SQLite ตาม `DATABASE_PATH` (มีไฟล์ `-wal` และ `-shm` คู่กัน) |
| รูปสลิปโอนเงิน | โฟลเดอร์ตาม `SLIP_STORAGE_PATH` ต้องอยู่นอกโฟลเดอร์ที่เสิร์ฟเป็นไฟล์สาธารณะ |
| รูปถ่ายสมาชิก · โลโก้ยิม | โฟลเดอร์ตาม `PHOTO_STORAGE_PATH` และ `LOGO_STORAGE_PATH` (ใน Docker คือ `/data/photos` และ `/data/logo`) |
| ภาพหน้าจอของเรื่องที่พนักงานแจ้ง | โฟลเดอร์ตาม `REPORT_STORAGE_PATH` (ใน Docker คือ `/data/reports`) **เปิดดูได้เฉพาะเจ้าของยิม และระบบบันทึกทุกครั้งที่มีคนเปิดดู** |

ข้อจำกัดที่ตามมาและมีผลกับทุกวิธี deploy:

- **ต้องมีดิสก์ถาวร (persistent disk)** host ที่ล้างไฟล์ทุกครั้งที่ deploy จะทำให้ข้อมูลสมาชิกและสลิปหายทั้งหมด
- **รันได้แค่ instance เดียว** ถ้ารันสองตัวจะแย่ write lock ของไฟล์เดียวกัน ต้องขยายเป็นเครื่องใหญ่ขึ้น ไม่ใช่เพิ่มจำนวน instance
- **ต้องเป็น HTTPS** เบราว์เซอร์ไม่ยอมให้เปิดกล้องแท็บเล็ตบน `http://` และตัวแอปเองก็ไม่ยอมสตาร์ตถ้า `APP_ORIGIN` ไม่ขึ้นต้นด้วย `https://` ตอน `NODE_ENV=production`
- **ต้องใช้ Node.js 24** เพราะฐานข้อมูลใช้ `node:sqlite` ซึ่งเสถียรตั้งแต่ 24 (บน Node 22 ต้องเปิด flag `--experimental-sqlite` และพฤติกรรมต่างกัน) ถ้าใช้ Dockerfile ในโปรเจกต์นี้จะได้เวอร์ชันถูกอยู่แล้ว

## ค่า env ที่ต้องตั้ง — เช็กลิสต์

คัดลอกจาก [`.env.example`](../.env.example) แล้วกรอก ค่าที่ทำเครื่องหมาย **ต้องมี** ถ้าไม่ตั้งแอปจะไม่สตาร์ต

| ตัวแปร | ต้องมี | ค่าที่ควรใช้ตอนขึ้นจริง |
|---|---|---|
| `NODE_ENV` | ✔ | `production` |
| `APP_ORIGIN` | ✔ | URL ของเว็บแบบเต็ม เช่น `https://app.suklutaifitness.com` **ต้องตรงเป๊ะ** ไม่มี `/` ปิดท้าย ถ้าผิดเบราว์เซอร์จะโดนปฏิเสธด้วย 403 ทุกคำขอที่เขียนข้อมูล และลิงก์ในจดหมายทุกฉบับ (ยืนยันอีเมล · ตั้งรหัสผ่านใหม่) จะพาไปผิดเครื่อง |
| `CARD_SIGNING_SECRET` | ✔ | สุ่ม 32 ไบต์: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` เซ็น session, โทเคนเช็คอิน และ **QR บนบัตรสมาชิกทุกใบ** — **เปลี่ยนเมื่อไหร่ ทุกคนหลุดออกจากระบบ และบัตรที่ส่งให้สมาชิกไปแล้วทุกใบใช้ไม่ได้** ตั้งครั้งเดียวแล้วอย่าแตะ |
| `PILOT_MODE` | | `1` เมื่อยังไม่มีบัญชีพร้อมเพย์ (ดูหัวข้อข้างล่าง) ลบบรรทัดทิ้งเมื่อจะรับโอนผ่านพร้อมเพย์ |
| `PROMPTPAY_ID` | | ใช้เฉพาะคิวสลิปเดิมที่ค้างจากแอปสมาชิกรุ่นก่อน เบอร์มือถือ / เลขบัตรประชาชน 13 หลัก / e-Wallet 15 หลัก **เป็นข้อมูลส่วนตัวของเจ้าของยิม ห้ามคอมมิตลง repo** |
| `TRUST_PROXY` | | จำนวน proxy ที่อยู่หน้าแอปจริง ๆ `1` ถ้ามี Caddy/nginx/Render/Fly ชั้นเดียว `2` ถ้ามี Cloudflare ซ้อนอีกชั้น **ตั้งผิดแล้วทั้งยิมจะใช้โควตา rate limit ร่วมกันก้อนเดียวจนล็อกอินไม่ได้** |
| `DATABASE_PATH` | | ต้องอยู่บนดิสก์ถาวร ค่าปริยายใน Docker คือ `/data/gym.sqlite` |
| `SLIP_STORAGE_PATH` | | ต้องอยู่บนดิสก์ถาวรและ**นอก** `dist/` ค่าปริยายใน Docker คือ `/data/slips` |
| `PHOTO_STORAGE_PATH` | | รูปถ่ายสมาชิก ต้องอยู่บนดิสก์ถาวรและ**นอก** `dist/` ค่าปริยายใน Docker คือ `/data/photos` |
| `LOGO_STORAGE_PATH` | | โลโก้ยิมที่เจ้าของอัปโหลดเอง ต้องอยู่บนดิสก์ถาวรและ**นอก** `dist/` ค่าปริยายใน Docker คือ `/data/logo` **ต้องอยู่ในชุดสำรองข้อมูล** |
| `REPORT_STORAGE_PATH` | | ภาพหน้าจอที่แนบมากับเรื่องที่พนักงานแจ้ง ต้องอยู่บนดิสก์ถาวรและ**นอก** `dist/` ค่าปริยายใน Docker คือ `/data/reports` **เป็นข้อมูลส่วนบุคคล** ภาพอาจมีชื่อและรูปสมาชิกที่อยู่บนจอตอนนั้น |
| `MACHINE_STORAGE_PATH` | | รูปเครื่องออกกำลังกายของยิม แสดงบนหน้าที่เปิดจาก QR ที่ติดเครื่อง ค่าปริยายใน Docker คือ `/data/machines` · **ไม่ใช่ข้อมูลส่วนบุคคล** (ใครสแกนก็เห็น) แต่ต้องอยู่บนดิสก์ถาวรและอยู่ในชุดสำรอง ไม่งั้นทุกหน้าเครื่องจะไม่มีรูปหลังกู้คืน |
| `SLIP_RETENTION_DAYS` | | `365` ตามนโยบายเก็บสลิป 1 ปี |
| `REPORT_RETENTION_DAYS` | | `180` เรื่องที่แจ้งและภาพหน้าจอเก็บครึ่งปี ล้างด้วย `npm run reports:prune` |
| `PORT` `HOST` | | `3000` และ `0.0.0.0` เมื่ออยู่ใน container |
| `ADMIN_EMAIL` `ADMIN_PASSWORD` | ✔ ตอน deploy ครั้งแรก | บัญชีแอดมินคนแรกกับรหัสผ่านของเขา (อย่างน้อย 12 ตัวอักษร) ระบบ hash รหัสผ่านลงฐานข้อมูลตอนบูตแรก **แล้วต้องลบทั้งสองค่าออกจาก `.env`** ตัวติดตั้ง bootstrap ลบให้เอง |
| `SETTINGS_ENC_KEY` | | คีย์ 32 ไบต์ที่ใช้เข้ารหัสรหัสผ่านกล่องจดหมายของยิมก่อนเก็บลงฐานข้อมูล สร้างครั้งเดียวด้วย `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` · **เว้นว่างได้ แอปยังรันปกติ** แต่หน้า “ตั้งค่าอีเมล” จะไม่ยอมรับรหัสผ่าน (ดีกว่าเก็บแบบไม่เข้ารหัส) · ทำหายไม่ถึงกับพัง แค่ให้เจ้าของยิมกรอกรหัสกล่องใหม่อีกครั้ง · **เปลี่ยนค่าทั้งที่มีรหัสเก็บอยู่** จะอ่านรหัสเดิมไม่ออก หน้าจอจะบอกว่ายังส่งไม่ได้ ไม่ใช่เงียบหาย |
| `SELF_SIGNUP` | | `1` = เปิดให้คนขอบัญชีพนักงานเองจากหน้าแรกเข้าคิวรออนุมัติ · **ค่าเริ่มต้นคือปิด** และยิมนี้ใช้แบบปิด หน้าแรกจึงมีแค่ “เข้าสู่ระบบ” กับ “ลืมรหัสผ่าน” บัญชีสร้างจากหน้า “ผู้ใช้และสิทธิ์” · โค้ดและเทสต์ของเส้นทางสมัครเองยังอยู่ครบ เปิดได้ทุกเมื่อโดยไม่ต้องแก้โค้ด |
| `ALLOW_DESTRUCTIVE_ROLLBACK` | | เว้นว่างไว้เสมอ ใส่ `yes` เฉพาะตอนจะรัน `db:rollback` จริง ๆ ครั้งเดียว |

**ค่าปริยายของห้าตัวบนนี้ตั้งไว้ในไฟล์ deploy ทั้งสามแบบแล้ว ไม่ต้องกรอกเองใน `.env`** — [`docker-compose.yml`](../docker-compose.yml) · [`fly.toml`](../fly.toml) · [`render.yaml`](../render.yaml) ทั้งสามชี้ไปใต้ `/data` ซึ่งเป็น volume เดียวที่รอดจากการ deploy รอบถัดไป
ถ้าตัวใดตัวหนึ่งหลุดไป แอปจะไม่ error — `SlipStore` สร้างโฟลเดอร์ให้เองในคอนเทนเนอร์ อัปโหลดสำเร็จ แล้วไฟล์หายเงียบ ๆ ตอน deploy รอบถัดไป และไม่มีสำเนาในชุดสำรอง เพราะ backup คัดลอกเฉพาะ `/data`
`tests/deploy-paths.test.js` อ่านโค้ดเซิร์ฟเวอร์ว่าใช้ `*_STORAGE_PATH` ตัวไหนบ้าง แล้วบังคับว่าไฟล์ deploy ทั้งสามต้องตั้งครบทุกตัวใต้ `/data` และ `deploy/entrypoint.sh` ต้อง `mkdir -p` ให้ครบ — โฟลเดอร์ที่เพิ่มในอนาคตจึงถูกครอบตั้งแต่วันแรก ทุกปลายทาง

## A. Hostinger VPS + Docker + Caddy (แนะนำ)

ต้องมี: VPS ที่มี Docker, โดเมนที่ชี้ A record มาที่ IP ของ VPS แล้ว, พอร์ต 80 และ 443 เปิด

```bash
git clone https://github.com/Gith-Akerit/Gym-Management-.git
cd Gym-Management-
git checkout release/pilot

cp .env.example .env
nano .env          # กรอกตามเช็กลิสต์ข้างบน และเพิ่ม APP_DOMAIN=app.example.com

./deploy/up.sh                    # = docker compose up -d --build บวกเลข commit
docker compose logs -f app        # ดูจนเห็น {"event":"ready","port":3000}
```

**ใช้ `./deploy/up.sh` แทน `docker compose up -d --build`** สคริปต์ต่างกันแค่อ่านเลข commit จาก git แล้วส่งเข้า build เป็น `APP_REVISION` ซึ่งติดไปกับทุกเรื่องที่พนักงานกดแจ้ง — ครึ่งหนึ่งของเรื่องจะมาถึงหลัง deploy รอบถัดไป ถ้าไม่มีเลขนี้จะบอกไม่ได้ว่าเรื่องนั้นพูดถึงหน้าจอเวอร์ชันไหน · รันคำสั่ง compose ตรง ๆ ก็ยังได้ แค่ช่องนั้นจะว่าง

Caddy จะขอใบรับรอง Let's Encrypt ให้เองภายในไม่กี่วินาทีหลัง DNS ชี้ถูก ไม่ต้องตั้งอะไรเพิ่มและไม่ต้องต่ออายุเอง

`docker compose up` จะรัน migrate และ seed ให้อัตโนมัติทุกครั้งที่บูต ทั้งสองคำสั่งข้ามสิ่งที่ทำไปแล้ว จึงปลอดภัยกับยิมที่มีข้อมูลอยู่แล้ว และ**ไม่ทับราคาหรือเวลาเปิดทำการที่เจ้าของยิมแก้ไว้**

อัปเดตเป็นเวอร์ชันใหม่:

```bash
docker compose exec app node -e "process.exit(0)"   # ยืนยันว่ายังรันอยู่
# สำรองก่อนเสมอ ดูหัวข้อ "สำรองและกู้คืน"
git pull
./deploy/up.sh
```

## B. Hostinger VPS + PM2 + nginx

```bash
# Node 24 (nvm หรือ NodeSource)
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash - && sudo apt install -y nodejs
sudo npm install -g pm2

git clone https://github.com/Gith-Akerit/Gym-Management-.git
cd Gym-Management- && git checkout release/pilot
npm ci && npm run build

cp .env.example .env && nano .env
npm run db:migrate && npm run db:seed
ADMIN_EMAIL=owner@example.com npm run db:admin

pm2 start deploy/pm2.config.cjs && pm2 save && pm2 startup

sudo cp deploy/nginx.conf /etc/nginx/sites-available/gym
sudo ln -s /etc/nginx/sites-available/gym /etc/nginx/sites-enabled/gym
sudo nano /etc/nginx/sites-available/gym     # แก้ server_name เป็นโดเมนจริง
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d app.example.com      # ออกใบรับรองและตั้งต่ออายุอัตโนมัติ
```

อัปเดต: `git pull && npm ci && npm run build && npm run db:migrate && pm2 restart gym`

## C. Fly.io

```bash
fly auth login
fly launch --no-deploy --copy-config        # ตอบ no เมื่อถามว่าจะสร้าง database
fly volumes create gym_data --size 1 --region sin
fly secrets set \
  CARD_SIGNING_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))") \
  APP_ORIGIN=https://<ชื่อแอป>.fly.dev \
  PROMPTPAY_ID=... \
  ADMIN_EMAIL=owner@example.com ADMIN_PASSWORD=...
fly deploy
```

ได้ `https://<ชื่อแอป>.fly.dev` พร้อม HTTPS ทันที ต่อโดเมนของตัวเองภายหลังด้วย `fly certs add app.example.com` แล้วอย่าลืมแก้ `APP_ORIGIN` ตาม

## D. Render

Push branch ขึ้น GitHub แล้วสร้าง Blueprint ชี้ไปที่ [`render.yaml`](../render.yaml) กรอกค่าที่ตั้ง `sync: false` ในหน้า dashboard
`CARD_SIGNING_SECRET` Render สุ่มให้เองครั้งเดียวแล้วเก็บไว้ **อย่ากด regenerate** เพราะทุกคนจะหลุดออกจากระบบและบัตรสมาชิกทุกใบที่ส่งไปแล้วจะใช้ไม่ได้

## โหมดทดลอง (Pilot Mode)

ตอนนี้โหมดทดลองมีความหมายเดียว: **ยังไม่ได้ผูกบัญชีพร้อมเพย์** พนักงานล็อกอินด้วยรหัสผ่านเหมือนกันทุกโหมด และสมาชิกไม่ต้องล็อกอินเลย ระบบจึงไม่ได้พึ่งผู้ให้บริการอีเมลอีกต่อไปไม่ว่าจะเปิดหรือปิดโหมดนี้

| | `PILOT_MODE=1` | ปิด (ปกติ) |
|---|---|---|
| ขายแพ็กเกจ | ที่หน้าสมาชิกรายคน (เงินสด/โอน/มอบให้) | เหมือนกัน |
| QR พร้อมเพย์ | ไม่มี | ใช้กับคำสั่งซื้อเดิมได้ |
| แถบเตือน "โหมดทดลอง" | แสดงทุกหน้า | ไม่แสดง |

ปิดโหมดนี้ทีหลังแล้วทุกอย่างที่สร้างไว้ยังอยู่ครบ: สมาชิก รูปถ่าย บัตร สิทธิ์ และประวัติเช็คอิน

### เข้าสู่ระบบครั้งแรก

แอดมินคนแรกและรหัสผ่านของเขามาจาก `ADMIN_EMAIL` กับ `ADMIN_PASSWORD` ตอนบูตแรก (ตัวติดตั้ง bootstrap ถามให้ที่ terminal แบบไม่แสดงบนจอ) จากนั้น **ลบทั้งสองค่าออกจาก `.env`** — ตัวติดตั้งลบให้เอง ส่วนถ้าตั้งเอง:

```bash
cd /srv/gym
npm run env:set -- ADMIN_EMAIL= ADMIN_PASSWORD=
```

บัญชีพนักงานคนต่อ ๆ ไปสร้างและตั้งรหัสผ่านได้จากหน้า **"ผู้ใช้และสิทธิ์"** ในแอป ไม่ต้องใช้ terminal อีก บัญชีที่ยังไม่ได้ตั้งรหัสผ่านจะเข้าระบบไม่ได้ และตารางในหน้านั้นบอกไว้ว่า "ยังไม่ได้ตั้ง"

**รหัสผ่านเก็บเป็น bcrypt (cost 12)** ไม่มีที่ไหนเก็บรหัสผ่านจริง การตั้งรหัสผ่านใหม่จะบังคับออกจากระบบทุกเครื่องของบัญชีนั้น ยกเว้นเครื่องที่กำลังตั้งอยู่ ลืมรหัสผ่านให้เจ้าของยิมตั้งใหม่ให้จากหน้าเดียวกัน — ไม่มีลิงก์รีเซ็ตทางอีเมล เพราะไม่มีระบบอีเมลแล้ว

### เปิด

ถ้าติดตั้งด้วยตัว bootstrap ของ Hostinger ให้ใส่ `--pilot` ในคำสั่งติดตั้ง (ดู [docs/bootstrap.md](bootstrap.md)) สคริปต์จะถามแค่อีเมลแอดมินกับรหัสผ่าน และข้ามคำถามพร้อมเพย์

ถ้าตั้งเอง:

```bash
cd /srv/gym
npm run env:set -- PILOT_MODE=1
# แล้วรีสตาร์ตบริการ: docker compose up -d  หรือ  pm2 restart gym
```

### ปิดเพื่อรับโอนผ่านพร้อมเพย์

ถ้าติดตั้งด้วย bootstrap ให้รันคำสั่งเดิม **โดยไม่ใส่ `--pilot`** สคริปต์จะถามเลขพร้อมเพย์ที่ขาด แล้วปิดโหมดทดลองและรีสตาร์ตให้เอง

ถ้าตั้งเอง:

```bash
cd /srv/gym
npm run env:set -- PILOT_MODE= PROMPTPAY_ID='08xxxxxxxx'
# แล้วรีสตาร์ตบริการ
```

ถ้าเปิด `PILOT_MODE=1` ทิ้งไว้ทั้งที่กรอกพร้อมเพย์แล้ว ตอนบูตจะมี log เตือนบอกว่าค่าไหนถูกข้าม

## รูปถ่ายสมาชิกและบัตร

รูปถ่ายสมาชิกเก็บแบบเดียวกับสลิป: **นอก web root** ชื่อไฟล์ระบบตั้งเอง ตัดข้อมูล EXIF (รวมพิกัด GPS) ทิ้งก่อนเขียนลงดิสก์ และเสิร์ฟผ่าน endpoint ที่ตรวจสิทธิ์เท่านั้น ตั้งที่เก็บด้วย `PHOTO_STORAGE_PATH` และ **ต้องรวมอยู่ในชุดสำรองข้อมูล** — ไม่มีรูปถ่ายแปลว่าพนักงานเทียบหน้าตอนสแกนไม่ได้

บัตรสมาชิกเป็นไฟล์ PNG ขนาด 1080 × 1350 ที่เซิร์ฟเวอร์วาดสด ๆ ทุกครั้งที่ขอ ไม่ได้เก็บเป็นไฟล์ จึงไม่ต้องสำรอง QR บนบัตรเป็นโทเคนถาวรที่เซ็นด้วย `CARD_SIGNING_SECRET` และมีเลขที่บัตร (`card_version`) อยู่ข้างใน กด "ออกบัตรใหม่" แล้วเลขนั้นเพิ่มขึ้น บัตรใบเก่าจึงใช้ไม่ได้ทันทีโดยไม่ต้องไปตามลบรูปที่ไหน

การวาดบัตรใช้ `@napi-rs/canvas` (มี binary สำเร็จรูป ไม่ต้องคอมไพล์) กับฟอนต์ Noto Sans Thai ที่มาจาก npm ทั้งคู่ติดตั้งมาพร้อม `npm ci` ถ้าเครื่องไหนโหลด binary ไม่ได้ ระบบยังเปิดร้าน สมัครสมาชิก รับเงิน และสแกนได้ตามปกติ — เฉพาะการสร้างรูปบัตรที่จะขึ้นข้อความบอกว่าทำไม่ได้

รูปถ่ายถูกย่อให้ด้านยาวไม่เกิน 700px ก่อนเขียนลงดิสก์ บัตรใช้รูปวงกลม 232px และหน้าสแกนใช้ราว 300px พิกเซลที่เหลือจากกล้องมือถือจึงเป็นแค่พื้นที่ดิสก์กับเวลารอที่ไม่มีใครเห็น

ปุ่ม **"ส่งบัตรซ้ำ"** ให้ลิงก์ที่เซ็นไว้ อายุ 7 วัน ดาวน์โหลดบัตร**ใบเดิม** ไม่ได้ออกใบใหม่ ลิงก์ไม่ได้เก็บเป็นแถวในฐานข้อมูล แต่ลายเซ็นครอบเลขที่บัตรไว้ กด "ออกบัตรใหม่" เมื่อไหร่ ลิงก์เก่าทุกอันตายพร้อมบัตรใบเก่าทันที

### เครื่องที่อัปเกรดมาจากรุ่นก่อน

- **`OTP_SECRET` → `CARD_SIGNING_SECRET`** ชื่อใหม่แต่**ค่าเดิม** เปลี่ยนแค่ชื่อคีย์ใน `.env` ห้ามสุ่มค่าใหม่ ถ้ายังใช้ชื่อเดิมอยู่ระบบยังอ่านได้และจะขึ้น log `secret_renamed` เตือนทุกครั้งที่เริ่มทำงาน
- **แอดมินที่ยังไม่มีรหัสผ่าน** (เครื่องที่ติดตั้งก่อนระบบรหัสผ่าน) สั่งบนเครื่องนั้น:
  ```bash
  npm run admin:set-password-link -- owner@example.com   # docker: docker compose exec app npm run ...
  ```
  บรรทัดแรกคือลิงก์ ใช้ได้ครั้งเดียว หมดอายุ 24 ชั่วโมง พาไปหน้าตั้งรหัสผ่านโดยไม่ต้องล็อกอิน และบันทึกลง audit log (`user.password_link_cli`) ทุกครั้งที่ออก ตั้ง `APP_ORIGIN` ไว้ก่อนจะได้ลิงก์เต็ม


## หลัง deploy: ตรวจ 8 ข้อนี้ก่อนบอกคนอื่นว่าใช้ได้

1. เปิด `https://<โดเมน>/api/health` ต้องได้ `{"status":"ok"}`
2. เข้าสู่ระบบด้วยอีเมลแอดมินกับรหัสผ่านที่ตั้งตอนติดตั้ง แล้วยืนยันว่า `ADMIN_EMAIL` กับ `ADMIN_PASSWORD` ถูกลบออกจาก `.env` แล้ว
3. กรอกข้อมูลยิมให้ครบ: เวลาเปิดทำการ เบอร์โทร ที่อยู่ — เบอร์โทรจะไปโผล่บนบัตรสมาชิกทุกใบ
4. ตั้งราคาแพ็กเกจอย่างน้อย 1 รายการแล้วเปลี่ยนสถานะเป็น active — **แพ็กเกจที่ยังไม่มีราคาขายไม่ได้**
5. สร้างบัญชีพนักงาน 1 บัญชีในหน้า "ผู้ใช้และสิทธิ์" แล้ว**ให้พนักงานคนนั้นตั้งรหัสผ่านเองจากลิงก์ใน "ลืมรหัสผ่าน" และล็อกอินจริงบนเครื่องของเขา** — หน้าจอไม่มีปุ่มตั้งรหัสผ่านให้คนอื่นแล้ว (รหัสที่คนอื่นตั้งให้ต้องบอกกันด้วยปาก ซึ่งลงเอยในกลุ่มแชททุกครั้ง) ทางเข้าสำรองเมื่อส่งเมลไม่ได้เลยคือ `npm run admin:set-password-link`
6. สมัครสมาชิกทดสอบ 1 คนที่เคาน์เตอร์ **ถ่ายรูปด้วยกล้องของเครื่องที่จะใช้จริง** (ไม่ใช่อัปโหลดไฟล์) แล้วรับเงินสดและมอบแพ็กเกจ
7. **ส่งรูปบัตรให้ตัวเองทาง LINE เปิดบนมือถืออีกเครื่อง แล้วเอาเครื่องที่หน้าเคาน์เตอร์สแกนจอจริง** ข้อนี้ข้ามไม่ได้ ซอฟต์แวร์ทดสอบแทนไม่ได้เรื่องโฟกัส แสงสะท้อน ความสว่างจอ และการที่ LINE บีบอัดรูป — ตรวจด้วยว่ารูปถ่ายบนจอพนักงานตรงกับคนที่ยืนอยู่
8. สั่งสำรองข้อมูลหนึ่งครั้งแล้ว**ลองกู้คืนบนเครื่องทดสอบ** ให้ครบทั้งฐานข้อมูล สลิป รูปถ่ายสมาชิก โลโก้ยิม **และภาพของเรื่องที่แจ้ง** สำรองที่ไม่เคยกู้คืนสำเร็จไม่นับว่าเป็นสำรอง
9. ตรวจว่าที่เก็บไฟล์ในคอนเทนเนอร์ชี้ลง volume จริงทุกตัว ถ้าตัวไหนไม่ขึ้นต้นด้วย `/data` แปลว่าไฟล์นั้นจะหายตอน deploy รอบหน้า:
   ```bash
   docker compose exec app printenv DATABASE_PATH SLIP_STORAGE_PATH PHOTO_STORAGE_PATH LOGO_STORAGE_PATH REPORT_STORAGE_PATH MACHINE_STORAGE_PATH
   ```
10. **ตรวจสองบรรทัดนี้ใน `.env` ทุกครั้งที่ deploy** — ทั้งคู่ QA ยกมาจากการทดสอบจริง:
   ```bash
   docker compose exec app printenv SETTINGS_ENC_KEY | wc -c   # ต้องได้ 65 (hex 64 ตัว + ขึ้นบรรทัด)
   docker compose exec app printenv SELF_SIGNUP                # ต้องว่าง ห้ามเป็น 1
   ```
   - **ต้องมี `SETTINGS_ENC_KEY`** ไม่งั้นหน้า "ตั้งค่าอีเมล" จะไม่ยอมรับรหัสผ่านเลย (ตอบ 409 พร้อมบอกชื่อตัวแปร ซึ่งถูกต้อง แต่แปลว่าเจ้าของยิมเปิดใช้อีเมลไม่ได้จนกว่าจะมีคีย์)
   - **ต้องไม่มี `SELF_SIGNUP=1`** เส้นทางสมัครเองยังอยู่ในโค้ดครบและปิดด้วย env เท่านั้น ตั้งพลาดเมื่อไหร่ ประตูหน้าเปิดให้คนทั้งอินเทอร์เน็ตส่งคำขอเข้าคิวอนุมัติทันที


## ย้ายเครื่อง หรือกู้คืนขึ้นเครื่องใหม่

**`SETTINGS_ENC_KEY` ไม่ได้อยู่ในชุดสำรอง** — ตั้งใจให้เป็นอย่างนั้น เพราะคีย์ที่อยู่ในไฟล์สำรองเดียวกับฐานข้อมูล
ก็คือคีย์ที่หลุดไปพร้อมกับฐานข้อมูล · ผลคือการย้ายเครื่องต้อง**ยกคีย์ไปเอง** และมีสองอย่างที่ต้องยกไปด้วยกัน:

| ยกไปด้วย | ถ้าลืม |
|---|---|
| `CARD_SIGNING_SECRET` | **บัตรสมาชิกทุกใบที่ส่งออกไปแล้วสแกนไม่ติด** และทุกคนถูกออกจากระบบ — กู้ไม่ได้ ต้องออกบัตรใหม่ทั้งยิม |
| `SETTINGS_ENC_KEY` | ระบบอ่านรหัสกล่องจดหมายเดิมไม่ออก · หน้าตั้งค่าอีเมลจะขึ้นว่า "มีรหัสผ่านอยู่แล้ว" แต่ "ยังส่งไม่ได้" และเจ้าของยิมต้องกรอกรหัสกล่องใหม่หนึ่งครั้ง (ไม่ได้เงียบ — ระบบบอกสถานะตรง QA ทดสอบแล้ว) |

ขั้นตอน: คัดลอก `.env` ของเครื่องเดิมไปเครื่องใหม่ **ก่อน** กู้คืน `/data` แล้วจึงกู้คืนไฟล์และรัน migrate
· ถ้าเครื่องเดิมยังอยู่ ให้ `npm run env:set -- --list` ทั้งสองเครื่องแล้วเทียบว่ามีคีย์ครบชุดเดียวกัน (คำสั่งนี้แสดงเฉพาะชื่อคีย์ ไม่แสดงค่า)

## สำรองและกู้คืน

```bash
# Docker: สำรองทั้ง volume ในคำสั่งเดียว
docker compose exec -T app sh -c 'sqlite3 "$DATABASE_PATH" ".backup /data/backup.sqlite"' 2>/dev/null \
  || docker compose stop app     # ถ้าไม่มี sqlite3 ใน image ให้หยุดบริการก่อนคัดลอก
docker run --rm -v gym-management-_gym-data:/data -v "$PWD":/out alpine \
  tar czf /out/gym-backup-$(date +%F).tar.gz -C /data .
docker compose start app
```

```bash
# PM2: หยุดบริการชั่วครู่แล้วคัดลอกให้ครบทั้งสามไฟล์
pm2 stop gym
cp data/gym.sqlite data/gym.sqlite-wal data/gym.sqlite-shm /backup/ 2>/dev/null
tar czf /backup/files-$(date +%F).tar.gz data/slips data/photos data/logo data/reports
pm2 start gym
```

ตั้ง cron ให้ทำทุกวันและเก็บย้อนหลังอย่างน้อย 7 วัน ขั้นตอนกู้คืนและแผนย้อนกลับเมื่อ deploy แล้วมีปัญหาอยู่ในหัวข้อ "แผนย้อนกลับ" ของ [`README.md`](../README.md)

รูปสลิปและภาพหน้าจอของเรื่องที่แจ้งเป็นข้อมูลส่วนบุคคล ต้องมี cron ลบของเก่าทั้งสองอย่าง (รูปถ่ายสมาชิกไม่ถูกลบ เพราะเป็นของที่ต้องใช้ทุกครั้งที่สมาชิกเดินเข้ามา):

```bash
0 3 1 * * cd /srv/gym && npm run slips:prune      # สลิป 365 วัน — เดือนละครั้งพอ
37 3 * * * cd /srv/gym && npm run reports:prune   # ภาพแจ้งปัญหา 180 วัน — ทุกวัน
```

ภาพแจ้งปัญหาลบทุกวันเพราะมันติดสิ่งที่อยู่บนจอตอนนั้นไปด้วย ซึ่งอาจเป็นชื่อและรูปของสมาชิก — "180 วัน" จึงต้องหมายถึง 180 ไม่ใช่ 180 บวกอีกไม่เกินหนึ่งเดือน

`deploy/bootstrap.sh` เขียนสองบรรทัดนี้ลง `/etc/cron.d/gym-pilot` ให้อยู่แล้วตอนติดตั้ง ถ้าติดตั้งเองแบบอื่นต้องตั้งเอง และ `tests/deploy-cron.test.js` จะไม่ผ่านถ้ามี script `*:prune` ตัวใหม่ที่ยังไม่มี cron

## พอร์ทัลสมาชิก "ช่วยเล่น" — เนื้อหาและแผ่น QR

เนื้อหาของพอร์ทัล (เครื่อง โปรแกรม บทความ ข้อความความปลอดภัย) อยู่ในไฟล์เดียวที่ `docs/content/member-content.json`
นำเข้าฐานข้อมูลด้วย:

```bash
npm run content:import                    # อ่าน docs/content/member-content.json
npm run content:import -- ./ไฟล์อื่น.json
```

**รันซ้ำได้ตลอด** — แถวที่มีอยู่แล้วจะถูกอัปเดต ไม่ใช่เพิ่มซ้ำ · และ**แถวที่เทรนเนอร์ของยิมตรวจแล้ว
(กดปุ่ม "ตรวจแล้ว" ในหน้าจัดการ) จะไม่ถูกเขียนทับ** สคริปต์จะพิมพ์บอกว่าแถวไหนถูกข้ามเพราะเหตุนี้
ถ้าไม่มีกติกานี้ การนำเข้ารอบถัดไปจากทีมจะลบสิ่งที่คนที่ยิมตัดสินใจไว้ทิ้งเงียบ ๆ

### ใครเห็นอะไร

| หน้า | ใครเปิดได้ |
|---|---|
| `/m/<รหัสเครื่อง>` เช่น `/m/M-01` · บทความ | **ทุกคน ไม่ต้องเข้าสู่ระบบ** — มี QR ติดอยู่ที่ตัวเครื่อง คนที่ยืนอยู่ตรงนั้นไม่มี session และจะไม่สมัครเพื่อดูวิธีใช้เครื่อง |
| หน้าแรก "ช่วยเล่น" · โปรแกรมฝึก | **สมาชิกที่สิทธิ์ยังไม่หมดอายุ** ตรวจทุกคำขอ ไม่ใช่ตอนล็อกอิน |
| หน้าจัดการเนื้อหา · แผ่น QR | เจ้าของยิมเท่านั้น |

หน้าเครื่องเป็น HTML ที่เซิร์ฟเวอร์เรนเดอร์ ไม่โหลด bundle ของแอปเลย เพราะคนอ่านยืนอยู่ข้างเครื่อง
ถือมือถือมือเดียว บนเน็ตของยิม · คลิปวิดีโอเป็นภาพนิ่งจนกว่าจะกด กดแล้วจึงสร้าง iframe

### แผ่น QR ติดเครื่อง

เจ้าของยิมเปิด `https://<โดเมน>/api/machines/qr-sheet` แล้วกด Ctrl+P · ได้ QR ทุกเครื่องในหน้าเดียว
ตัดตามเส้นประแล้วติดที่เครื่อง · คนที่สแกนไม่ต้องเข้าสู่ระบบ

### รูปเครื่อง

ยิมถ่ายเองตามรายการใน `photo_shotlist` ของไฟล์เนื้อหา แล้วอัปโหลดทีละเครื่องจากหน้าจัดการ
เก็บใน `MACHINE_STORAGE_PATH` (`/data/machines` ใน Docker) ซึ่งอยู่ในชุดสำรองเหมือนโฟลเดอร์อื่น

### ส่งอีเมลเป็นคิว

จดหมายทุกฉบับออกทีละฉบับโดยเว้นระยะ ~2 วินาที เพราะ Office 365 รับราว 30 ฉบับต่อนาทีต่อกล่อง
ยิมนี้ไม่มีทางถึงเพดานในวันปกติ แต่วันที่มีคนนำเข้ารายชื่อสมาชิกทีเดียวหลายสิบคน กล่องจะถูกจำกัด
และจดหมายที่ถูกปฏิเสธจะอ่านเหมือนรหัสผ่านผิดบนหน้าตั้งค่า — เว้นระยะไว้ตัดปัญหาทั้งกองนี้ทิ้ง

## เปิดการส่งอีเมล (ทำครั้งเดียว เจ้าของยิมทำเองได้)

ยิมส่งจดหมายผ่าน **กล่อง Office 365 ของยิมเอง** (`info@suklutai.co.th`) ไม่ใช้ผู้ให้บริการภายนอก ไม่มีค่าใช้จ่ายเพิ่ม และผู้รับเห็นอีเมลที่เขารู้จัก

**ค่าทั้งหมดกรอกในแอป ไม่ได้อยู่ใน `.env`** — เพราะคนที่รู้รหัสผ่านกล่องจดหมายคือเจ้าของยิม และหน้าจอเดียวที่เขาเข้าถึงได้คือแอป การให้เขาส่งรหัสผ่านมาทางแชทเพื่อให้ทีมไปใส่ในไฟล์ คือวิธีที่ทำให้รหัสนั้นไปอยู่ในประวัติแชทสามที่

### ฝั่งเครื่อง (ทำก่อน ครั้งเดียว)

```bash
cd /srv/gym
npm run env:set -- SETTINGS_ENC_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
npm run env:set -- --list          # ยืนยันว่ามีคีย์แล้ว โดยไม่แสดงค่า
docker compose restart app         # หรือ pm2 restart gym
```

ติดตั้งใหม่ไม่ต้องทำข้อนี้ — `bootstrap-env.py` สร้าง `SETTINGS_ENC_KEY` ให้ตั้งแต่ตอนติดตั้งแล้ว ข้อนี้มีไว้สำหรับเครื่องที่ติดตั้งไปก่อนหน้านี้

### ฝั่ง Microsoft 365 (ผู้ดูแล M365 ของยิมทำ ครั้งเดียว)

1. **เปิด Authenticated SMTP ให้กล่อง `info@`** — Microsoft 365 admin center → Users → เลือกผู้ใช้ → Mail → Manage email apps → ติ๊ก **Authenticated SMTP**
   ถ้าไม่เปิด จะล็อกอินไม่ผ่านแม้รหัสถูก และข้อความที่ได้จะอ่านเหมือนรหัสผิด
2. ถ้ากล่องเปิดยืนยันตัวตนสองขั้น ให้สร้าง **App password** สำหรับกล่องนี้ แล้วใช้รหัสนั้นแทนรหัสปกติ

### ฝั่งแอป (เจ้าของยิมทำเอง ไม่ต้องส่งรหัสให้ใคร)

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ → เมนูมุมขวาบน → **ตั้งค่าอีเมล**
2. ค่าเริ่มต้นเป็นของ Office 365 อยู่แล้ว (`smtp.office365.com` พอร์ต `587`) ไม่ต้องแก้
3. กรอกชื่อผู้ใช้และอีเมลผู้ส่งเป็น `info@suklutai.co.th` และกรอกรหัสผ่านของกล่องนั้น แล้วกด **บันทึกการตั้งค่าอีเมล**
4. กด **“ส่งเมลทดสอบถึงตัวเอง”** — จดหมายจะไปที่อีเมลของบัญชีที่กำลังใช้อยู่ ไม่ใช่อีเมลที่พิมพ์ในช่องไหน

### ตรวจว่าผ่านจริง

เปิดจดหมายที่ได้รับแล้วดูสามอย่าง ก่อนบอกว่าใช้ได้:

- **ชื่อผู้ส่งเป็นชื่อยิม** ไม่ใช่ `info` หรือ `noreply`
- **ภาษาไทยอ่านออกทั้งฉบับ** ทั้งหัวเรื่องและเนื้อ (หัวเรื่องที่ encoding ผิดจะขึ้นเป็น `=?utf-8?...` หรืออักษรขยะ)
- เปิดซ้ำบน**มือถือ** จดหมายไม่มีรูปและไม่มีสคริปต์เลย จึงควรเหมือนกันทุกที่

ถ้าไม่ผ่าน หน้าจอจะบอกสาเหตุเป็นภาษาคนอยู่แล้ว ส่วนใน log ดูได้ที่:

```bash
docker compose logs --since 10m app | grep -E 'mail_failed|mail_skipped'
```

| ที่เห็น | แปลว่า |
|---|---|
| `mail_skipped` | ยังไม่ได้กรอกหน้า “ตั้งค่าอีเมล” ให้ครบ (หรือ `SETTINGS_ENC_KEY` หายไปหลังจากเก็บรหัสไว้แล้ว) |
| `mail_failed` `reason: auth` | รหัสผ่านผิด **หรือยังไม่ได้เปิด Authenticated SMTP** — เกือบทุกครั้งคืออย่างหลัง |
| `mail_failed` `reason: sender` | อีเมลผู้ส่งไม่ตรงกับกล่องที่ล็อกอิน |
| `mail_failed` `reason: network` | เครื่องออกไปพอร์ต 587 ไม่ได้ |

### ระหว่างที่ยังไม่ได้ตั้งค่าอีเมล

ทุกหน้าจอทำงานเหมือนเดิมทั้งหมด ต่างแค่ไม่มีจดหมายออกไป และมีทางสำรองเตรียมไว้แล้ว:

- **พนักงานลืมรหัสผ่าน / ได้บัญชีใหม่** — ผู้ดูแลระบบเปิดหน้า “ผู้ใช้และสิทธิ์” กด **“สร้างลิงก์ตั้งรหัสผ่าน”** ที่แถวของเขา แล้วคัดลอกลิงก์ส่งให้เจ้าตัวเอง ลิงก์ใช้ได้ **24 ชั่วโมง ครั้งเดียว**
- **หน้าลืมรหัสผ่านฝั่งสาธารณะไม่เคยแสดงลิงก์บนจอ** ไม่ว่าใครกด — ถ้าแสดง ใครก็ตั้งรหัสผ่านบัญชีคนอื่นได้จากหน้าที่ไม่ต้องล็อกอิน
- **ทางเข้าสำรองสุดท้าย** เมื่อไม่มีผู้ดูแลระบบเหลืออยู่เลย: `npm run admin:set-password-link -- <email>` ที่เครื่อง
- **บัตรสมาชิก** ยังส่งให้ลูกค้าได้ตามปกติผ่าน “ส่งบัตรให้ลูกค้า” และลิงก์ 7 วัน

## สิ่งที่ยังต้องทำด้วยของจริงเท่านั้น

ทั้งสามข้อนี้ QA ยืนยันว่าทดสอบด้วยซอฟต์แวร์แทนไม่ได้ และต้องทำก่อนเปิดให้สมาชิกจริงใช้

1. **ส่งรูปบัตรผ่าน LINE จริง แล้วสแกนจากจอมือถือจริง** ด้วยเครื่องที่จะใช้หน้าเคาน์เตอร์ — LINE บีบอัดรูป และไม่มีอะไรทดสอบแทนได้ว่า QR ยังอ่านติดหลังบีบอัดบนจอที่หรี่แสง
2. **ถ่ายรูปสมาชิกด้วยกล้องของเครื่องจริง** ทั้งบนมือถือและบนคอมที่หน้าเคาน์เตอร์ (สิทธิ์กล้องของเบราว์เซอร์และคุณภาพกล้องต่างกันทุกเครื่อง)
3. **สแกน QR PromptPay ด้วยแอปธนาคารจริง** ถ้ายังมีคำสั่งซื้อค้างจากแอปสมาชิกรุ่นก่อน
